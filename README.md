# The Undergrad Builder's Guide

> Grades show you can learn. Projects, contributions and writing show you can **do**.
> A few years from now, people will look at what you built, what you shipped, and what you explained to others.

This folder is a practical playbook for getting involved in **research, open source, side projects, and technical writing** as an undergraduate.

## The core loop

```
   Learn something  ──►  Build / contribute  ──►  Document it  ──►  Share it (blog, talk, post)
          ▲                                                                  │
          └──────────────── feedback, new people, new ideas ◄────────────────┘
```

Every cycle of this loop produces something people can see: a merged PR, a repo, a paper, a blog post. That body of public work is your real résumé.

## Five rules of thumb

1. **Start small, start now.** A typo fix merged this week beats a perfect plan for next semester.
2. **Depth beats breadth.** Ten PRs to one project > one PR to ten projects. Five polished repos > fifty abandoned ones.
3. **Finish things.** A small finished project with a README, a demo, and a blog post is worth more than an ambitious half-done one.
4. **Work in public.** Push code to GitHub, write about what you learned, post progress. Opportunities find people who are visible.
5. **People > projects.** The mentors, labmates and collaborators you meet will open more doors than any single line of code.

## Quick start (this week)

- [ ] Clean up your GitHub profile (photo, bio, pinned repos, a profile README)
- [ ] Pick **one** open-source project you actually use and read its `CONTRIBUTING.md`
- [ ] Pick **one** professor/lab whose work interests you and read 2 of their recent papers
- [ ] Write down **3** project ideas that solve a problem you personally have
- [ ] Set up a blog (see [05-document-and-blog.md](05-document-and-blog.md)) and write a "Hello, here's what I'm learning" post
- [ ] Copy the tracker in [06-roadmap-and-tracker.md](06-roadmap-and-tracker.md) and fill in your first goals
